# CarbonHV host integration

`carbonhvd` is the narrow privileged broker used by an integrated Android host build. The Rust crate validates caller identity, VM generation, resource limits, managed image IDs, and launch parameters before any backend-specific launch occurs. The root `Android.bp` builds the same Rust sources for `system_ext`, publishes `dev.carbonhv.broker`, and links the generated Rust binding for `dev.carbonhv.host.runtime`.

The first development backend targets Android's AVF `vm` tool at `/apex/com.android.virt/bin/vm` and `/dev/kvm`. The initial display integration is pinned to AOSP `packages/modules/Virtualization` `android17-release` at `22f1c9ee92b146e10c8f5e71338618f77ab1631e`, matching the Pixel 7a Android 17 bring-up build used on 2026-09-27.

For that branch, the privileged `host/android` module follows AOSP Terminal's native display path exactly: obtain `android.system.virtualizationservice` through `ServiceManager`, call `IVirtualizationServiceInternal.waitDisplayService()`, convert the returned Binder to `ICrosvmAndroidDisplayService`, then use `setSurface(surface, false)` and `removeSurface(false)` for the main display. These are platform/internal interfaces and remain outside the ordinary CarbonHV APK.

Android 17 exposes one process-global crosvm display-service Binder through `VirtualizationServiceInternal`. CarbonHV therefore reserves one generation-scoped foreground display session before spawning a graphical crosvm. A stale generation or a second display owner is rejected before it can touch the platform Surface.

`CarbonHvHostIntegration` is a platform-API, platform-signed privileged `system_ext` app for a controlled host build. It uses the system shared UID for DAC access to the private `system:system` VM object store while running in the dedicated `carbonhv_host_app` SELinux domain. UI calls are accepted only when the caller's current signing certificate matches the SHA-256 digest configured by the host product in `ro.carbonhv.ui_signing_sha256`; a missing property fails closed. Authenticated lifecycle intent is forwarded to `dev.carbonhv.broker`, while graphical AVF launch/stop arrives back over the separate `dev.carbonhv.host.runtime` interface.

SELinux keeps those directions distinct: `carbonhvd` alone publishes the broker service and `carbonhv_host_app` alone finds/calls it; `carbonhv_host_app` alone publishes the host runtime service and `carbonhvd` alone finds/calls it.

The files `carbonhvd.te`, `carbonhv_host_app.te`, `service_contexts`, `file_contexts`, `seapp_contexts`, and `property_contexts` define CarbonHV's owned policy boundary. `host/product/carbonhv.mk` is the reusable Android 17 product entrypoint: it installs both CarbonHV host modules, imports this policy as `system_ext` private policy, and requires the ordinary UI signing digest at product-build time. `carbonhvd.rc` creates `/data/misc/carbonhv/{objects,runtime}` as private `system:system` storage and restores the dedicated label. crosvm receives already-opened image descriptors and is granted read/write operations on that label without `open`. These files must be merged into the selected Android 17 platform/private policy and compiled there; source-level contract tests are not proof that the target product policy accepts them.

The Rust Android broker service now accepts only the system-UID host bridge, resolves the initial GrapheneOS/Ubuntu Touch profiles to managed object IDs, chooses and validates generations, and invokes the host runtime through a lazy typed Binder client. The host service does not synthesize broker state from the UI; its authoritative live-generation query is forwarded to the Rust broker, and exact-generation AVF death is reconciled back into that broker.

The broker never accepts a shell command. Runtime requests reference broker-managed object IDs. The legacy development/headless backend still produces an argv-only `vm` launch plan. The graphical Android 17 path instead publishes a validated typed plan over Binder; `CarbonHvHostIntegration` lets the shipping framework create the exact raw AVF configuration while preserving CarbonHV's vCPU limit, gfxstream Vulkan/composer profile, display geometry, and input sockets.
