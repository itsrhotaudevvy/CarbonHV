# CarbonHV V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a runnable, testable CarbonHV v1 codebase implementing the native Android manager, deterministic bundle/instance core, authenticated host-broker contract, development AVF backend, virtual-device guest definitions, update/backup tooling, and qualification harness described by the architecture.

**Architecture:** The Android app is a Kotlin/Compose shell backed by a small platform-neutral Kotlin domain module. Privileged host execution is isolated behind a versioned broker protocol; the first concrete backend is a development AVF adapter that targets `/apex/com.android.virt/bin/vm`, with a Rust broker/core providing validation, lifecycle, bundle, and runtime policy. Guest bundles are declarative and reproducible; GrapheneOS-derived and Ubuntu Touch entries ship as port recipes and qualification contracts because their multi-gigabyte OS images are build artifacts rather than source-repository contents.

**Tech Stack:** Android SDK 36, AGP 9.0.1, Kotlin 2.3.20, Jetpack Compose 2026.03.01, Rust 1.98, Gradle 9.1, shell/Python build tooling where appropriate.

**Spec:** `docs/ARCHITECTURE.md`

## Global Constraints

- ARM64 hardware virtualization is the production execution target; no silent software CPU-emulation fallback.
- Native Android UI uses Kotlin/Compose, with a dedicated Android `SurfaceView` session surface.
- Privileged control is behind a narrow authenticated broker interface rather than a generic root shell.
- Guest bundles target a versioned Carbon Virtual Device contract and keep immutable system artifacts separate from private instance state.
- GrapheneOS is described as a CarbonHV-maintained GrapheneOS-derived virtual-device build unless upstream explicitly supports it.
- Ubuntu Touch is an actual Ubuntu Touch/Lomiri port, not a generic Ubuntu desktop image.
- Non-protected GUI VMs are the v1 baseline; protected GUI execution stays a separately qualified profile.
- One foreground VM is the v1 runtime baseline.
- Unsupported host capabilities fail closed and remain visible in diagnostics.
- Host/guest sharing is explicit, revocable, bounded, and disabled by default where the architecture specifies Private mode.

## Review Focus

- Malformed or oversized bundle metadata must be rejected before it can create paths or runtime arguments.
- Stale lifecycle/session generations must never acquire a second writer for a VM disk.
- Unsupported host capability combinations must produce an explicit admission failure without selecting an emulation fallback.
- Broker command construction must keep guest strings out of shell parsing and arbitrary host paths.
- Interrupted installs/updates must leave either the old usable state or reclaimable staging state, never a partially published bundle.
